# AUTEDI — AI 첨삭 프로토타입

Vite + React + TypeScript로 만든 교사용 영어 첨삭 UI 프로토타입입니다. 업로드와 예시 이미지, 첨삭 설정, AI 피드백 검토, 교사 코멘트 편집을 목업 데이터로 확인할 수 있습니다.

## 실행

```bash
npm install
npm run dev
```

정적 배포 전 확인:

```bash
npm run lint
npm run build
```

## 코드 구조

- `src/design-system/`: 디자인 토큰과 버튼·설정 카드 등 공통 UI
- `src/components/`: 앱 셸과 홈·업로드·생성 단계 화면
- `src/features/review/`: 첨삭 도메인 타입·샘플 데이터와 Konva 캔버스/검토 UI
- `src/store/`: Zustand 기반 화면 및 편집 상태
- `src/services/`: 첨삭 생성 목업 서비스. 실제 API 연동 시 이 경계를 교체

첨삭 서버 요청은 `src/services/reviewService.ts`에서 시작하도록 분리했습니다. 현재는 정해진 샘플 피드백을 돌려주며, API 연결 시 이 함수의 요청·응답 타입을 실제 계약에 맞추면 화면 컴포넌트는 그대로 유지할 수 있습니다. 서버 자격 증명은 브라우저 코드에 저장하지 마세요.

## 현재 프로토타입 범위

- JPG/PNG 이미지 업로드 및 제공된 손글씨 예시 이미지 사용
- 첨삭 영역별 기본 설정과 이번 작업에만 적용하는 설정
- 샘플 AI 피드백 확인·반영·삭제·추천 문장 수정
- Konva 캔버스에서 첨삭 표시 선택 및 이동
- 표시 영역을 드래그해 선택한 뒤 교사 코멘트 저장·삭제
- 이력 관리와 학생 관리는 원본 프로토타입처럼 준비 중/권한 없음 상태

## API 연동 전 확인 사항

백엔드와 아래 항목을 먼저 합의하면 프런트엔드와 API 계약을 안정적으로 맞출 수 있습니다.

### 1. 인증과 권한

- 로그인 방식과 인증 정보 전달 방식(예: 세션 쿠키 또는 Bearer 토큰)
- 토큰 만료·갱신 및 로그아웃 처리
- 교사별 학습지 접근 권한과 학생 관리 권한
- AI 제공자 키 등 비밀 자격 증명은 서버에만 보관하고 브라우저에 포함하지 않기

### 2. 이미지 업로드와 파일 정책

- 허용 형식, 최대 파일 크기, 페이지 수와 파일 크기 제한
- PDF 업로드를 지원할지, 지원한다면 서버에서 페이지 이미지로 변환할지
- 앱 서버로 직접 업로드할지, presigned URL로 오브젝트 스토리지에 직접 업로드할지
- 이미지 회전(EXIF), 크기 조정·압축, 업로드 진행률 처리
- 업로드 실패·취소 후 임시 파일 정리 및 재시도 정책
- 업로드 완료 응답에서 반환할 `imageId`, 파일 메타데이터와 이미지 조회 방법

현재 화면은 JPG/PNG 이미지를 사용하며, 업로드한 파일은 브라우저의 임시 `blob:` URL로 미리 봅니다. 이 URL은 영속 저장소가 아니므로 실제 서버 업로드와 재조회 계약이 필요합니다. 업로드 상태는 [UploadScreen.tsx](./src/components/UploadScreen.tsx), 클라이언트 상태는 [useAppStore.ts](./src/store/useAppStore.ts)에서 확인할 수 있습니다.

### 3. 첨삭 생성 작업

- 첨삭 요청이 `imageId`와 선택된 첨삭 설정을 어떤 형식으로 받는지
- 응답을 한 번에 반환할지, 작업 ID를 반환하고 진행 상태를 별도 조회할지
- 비동기 작업의 상태 값, 진행률, 완료·실패 상태와 예상 대기시간
- 생성 중 취소·재시도 정책과 중복 요청 방지(idempotency) 키
- OCR 실패, 인식률이 낮은 결과, 일부 영역만 분석에 성공한 경우의 처리 방식
- API 타임아웃과 일시적인 오류의 재시도 가능 여부

현재 목업 생성 함수는 [reviewService.ts](./src/services/reviewService.ts)에 있으며, 실제 API 연결 시 화면이 직접 `fetch`를 호출하기보다 이 서비스 경계를 교체하는 방식을 권장합니다.

### 4. 첨삭 결과와 캔버스 좌표

API 응답에서 최소한 아래 데이터의 의미와 필수 여부를 정해야 합니다.

- 피드백의 안정적인 `id`, 첨삭 종류, 분류, 원문, 추천 문장, 수정 이유
- 이미지 위 첨삭 영역의 `x`, `y`, `width`, `height` 및 코멘트 표시 위치
- 이미지 또는 페이지 식별자와 페이지 번호(다중 페이지 지원 시)
- 원본 이미지의 너비·높이, 방향, 크롭·회전 적용 여부
- 좌표 기준: 원본 픽셀, 0~1 정규화 좌표 또는 0~100 정규화 좌표

현재 [types.ts](./src/features/review/types.ts)의 `FeedbackItem`은 `x`, `y`, `width`, `height`, `noteY`를 사용하고, 캔버스는 이미지의 표시 크기에 맞춰 위치를 변환합니다. 서버와 좌표 원점, 축 방향, 단위, 기준 이미지(회전 전/후)를 일치시키지 않으면 마커 위치가 어긋날 수 있습니다. 이미지 원본·썸네일·방향이 바뀌어도 같은 위치를 재현할 수 있는 좌표 규격을 합의하세요.

### 5. 편집 내용 저장과 내보내기

- AI 피드백 반영·삭제·추천 문장 수정과 교사 코멘트 추가·이동·삭제를 즉시 저장할지
- 화면에서 임시 편집 후 저장 버튼을 눌렀을 때 한 번에 저장할지
- 초안, 저장됨, 완료 등 작업 상태와 저장 버전 관리 방식
- 동시 편집 또는 오래된 데이터를 저장할 때 충돌을 감지하는 방법
- 저장 실패 시 화면 상태를 되돌릴지, 재시도할 수 있도록 로컬 변경을 보존할지
- PDF를 서버에서 생성할지, 생성 완료 후 다운로드 URL을 반환할지
- 작업 이력·재접속 후 복구 및 최종 삭제 처리

현재 화면의 저장 버튼과 PDF 출력 버튼은 API 동작을 수행하지 않는 프로토타입 상태입니다. 편집 작업의 단위와 저장 시점을 정한 다음 API 계약을 추가해야 합니다.

### 6. 오류·네트워크 상태

- 오류 응답 형식과 사용자 메시지에 사용할 오류 코드
- 인증 만료, 권한 없음, 파일 형식·크기 오류, OCR/AI 실패를 구분하는 방법
- 요청별 제한 시간, 재시도 횟수, 오프라인 상태 처리
- 다른 화면으로 이동한 뒤 늦게 도착한 응답이 현재 상태를 덮어쓰지 않도록 요청 취소 또는 요청 ID를 관리하는 방법
- 로딩·진행·빈 결과·부분 실패·재시도 UI 동작

서버 오류는 성공한 것처럼 조용히 처리하지 말고, 사용자가 다음 행동을 알 수 있도록 명시적으로 표시해야 합니다.

### 7. 개인정보·보안·운영 환경

- 학생 이름·손글씨 이미지의 민감도, 저장 위치, 보관 기간과 삭제 요청 처리
- 이미지가 외부 OCR/AI 사업자에게 전달되는지, 해당 사업자의 보관·재사용 정책
- 전송 중·저장 시 암호화, 접근 제어, 감사 로그와 백업 정책
- 로그·오류 추적에 이미지나 학생의 원문이 포함되지 않도록 하는 정책
- 개발·스테이징·운영 API 주소, CORS와 파일 스토리지 도메인 설정

### 권장 API 경계 예시

아래는 계약 협의를 시작하기 위한 예시이며, 실제 경로·HTTP 메서드·요청 형식은 백엔드 규격에 맞춰 확정해야 합니다.

1. **이미지 업로드**: 이미지 파일을 업로드하고 `imageId`, 크기, 페이지 정보를 반환
2. **첨삭 생성 요청**: `imageId`와 첨삭 설정을 받고 `reviewId` 또는 작업 ID를 반환
3. **진행 상태/결과 조회**: 작업 상태와 완료 시 피드백 목록·좌표를 반환
4. **첨삭 저장**: 편집된 피드백과 교사 코멘트를 초안/완료 상태로 저장
5. **PDF 내보내기**: 저장된 첨삭을 PDF로 생성하고 다운로드 방법을 반환

우선 합의할 핵심 항목은 **이미지 업로드 방식, 좌표 규격, 첨삭 생성의 비동기 여부, 편집 결과의 저장 시점**입니다.


## 로컬 첨삭 사용

- 예시 학습지는 선택한 영역과 Standard/Advanced 강도에 따른 목업 피드백을 제공합니다. 실제 OCR 또는 AI 분석은 하지 않습니다.
- JPG/PNG(최대 20MB)를 업로드하면 교사가 영역을 선택하고 코멘트를 작성할 수 있습니다. 다른 사진에 예시 피드백을 표시하지 않습니다.
- 저장 버튼은 이미지·첨삭·교사 코멘트·반영 상태·세션 설정을 현재 브라우저의 IndexedDB에 보관합니다. 새로고침 후 홈의 최근 작업에서 다시 열 수 있습니다. 저장한 작업을 다시 저장하면 갱신합니다. 저장 버튼을 누르기 전의 변경 사항은 자동 저장되지 않습니다.
- PDF 출력은 브라우저 인쇄 창을 엽니다. 대상을 ‘PDF로 저장’으로 선택하면 원본 위 번호 표시와 전체 첨삭 설명을 출력할 수 있습니다.
- 브라우저 사이트 데이터를 삭제하면 저장 작업도 삭제됩니다. 서버나 외부 API로 전송하지 않습니다.

검증: `node --test tests/review.test.mjs`, `npm run lint`, `npm run build`
